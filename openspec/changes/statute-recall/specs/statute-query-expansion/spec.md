# Spec Delta

## Purpose

定义通用词如何被归一化为法规语料使用的受控术语、扩展查询如何构造与限流，以及"法规被检索过但没有被采用"这件事如何如实告诉用户。

## ADDED Requirements

### Requirement: 通用词必须按配置归一化为受控术语

系统 SHALL 在检索前用**配置驱动**的映射表把问题中的通用词扩展为受控术语；映射 MUST 可审计（记录本次实际使用了哪些扩展词），MUST NOT 由模型即时生成。问题中的精确标识（规则编号、金额、日期）MUST 保持不变。

#### Scenario: 命中映射表

- **WHEN** 问题包含映射表中的通用词
- **THEN** 发给法规服务的查询 MUST 同时包含原句与该词对应的受控术语
- **AND** 本次使用的扩展词 MUST 可追溯

#### Scenario: 未命中映射表

- **WHEN** 问题不包含任何映射词
- **THEN** 查询 MUST 与扩展前完全一致

#### Scenario: 精确标识

- **WHEN** 问题包含规则编号或金额
- **THEN** 这些标识 MUST 原样出现在查询中

### Requirement: 扩展必须有上限

扩展术语的数量与总字符数 MUST 有上限，超出部分 MUST 被丢弃而不是无限拼接，以免查询被堆词淹没。

#### Scenario: 映射项过多

- **WHEN** 命中多个映射词且扩展总数超过上限
- **THEN** 系统 MUST 只保留上限以内的术语
- **AND** MUST 不因此报错或拒绝检索

### Requirement: 法规被检索但未采用时必须说明

当法规检索返回了结果却被判定为不可用（低置信、未覆盖、服务不可用等）时，答案 MUST 说明"法规已检索但未采用"及原因与命中条数，**即使该回答已经由本地语料作答**。MUST NOT 让用户误以为"系统没有查法规"。

#### Scenario: 低置信且有本地答案

- **WHEN** 法规命中若干条但置信度低，本地语料给出了答案
- **THEN** 回答 MUST 说明法规命中条数与未采用原因
- **AND** 引用 MUST 仍来自本地语料

#### Scenario: 零命中

- **WHEN** 法规检索没有命中
- **THEN** 回答 MUST 说明"没有匹配到法规"，MUST NOT 表述为"没有相关规定"

### Requirement: 检索层必须暴露命中条数

每次运行的法规检索层 MUST 携带本次从法规服务取得的命中条数，使前端与回答能区分"查了但没有"与"没查"。

#### Scenario: 前端展示

- **WHEN** 用户查看某次回答的来源信息
- **THEN** 法规层 MUST 显示命中条数（含 0）
- **AND** 显示未采用原因（若有）
